## [easy] RISC-V assembly

本节作业需要阅读 call.asm 的汇编源码，并回答相应问题即可。

### 哪些寄存器包含传递给函数的参数？例如，在 `main` 调用 `printf` 时，哪个寄存器保存了 13？

在 call.c 的 `main` 函数中分别调用了 `printf` 、`exit` 函数并传递了参数。

```C
void main(void) {
  printf("%d %d\n", f(8)+1, 13);
  exit(0);
}
```

阅读汇编可以看到参数都放在了寄存器 `a0` 、`a1` 、`a2` ，三者分别存储了 "%d %d\n" 字符串的地址和两个整型参数。

```assembly
printf("%d %d\n", f(8)+1, 13);
2c:	4635                	li	a2,13
2e:	45b1                	li	a1,12
30:	00000517          		auipc	a0,0x0
```

对于后续的 `exit` 同理，所以整个代码中用于传递参数的寄存器有 `a0` 、`a1` 、`a2` ，调用 `printf` 时传入 13 的寄存器是 `a2` 。

### 在 main 的汇编代码中，对函数 f 的调用在哪里？对 g 的调用在哪里？（提示：编译器可能会内联函数。）

在编译后的 call.asm 中， `g` 函数的整个函数体为：

```assembly
int g(int x) {
   0:	1141                	addi	sp,sp,-16
   2:	e406                	sd	ra,8(sp)
   4:	e022                	sd	s0,0(sp)
   6:	0800                	addi	s0,sp,16
  return x+3;
}
   8:	250d                	addiw	a0,a0,3
   a:	60a2                	ld	ra,8(sp)
   c:	6402                	ld	s0,0(sp)
   e:	0141                	addi	sp,sp,16
  10:	8082                	ret
```

`return x+3;` 前都是在开辟栈空间，实际上只有 `addiw a0,a0,3` 这一条为真正的函数体，该指令后面的指令都是在回收栈空间。

对于 `f` 同理，`f` 由于是直接对 `g` 的调用，最后编译出的函数真正的函数体也只是 `addiw a0,a0,3` 。

```C
int f(int x) {
  12:	1141                	addi	sp,sp,-16
  14:	e406                	sd	ra,8(sp)
  16:	e022                	sd	s0,0(sp)
  18:	0800                	addi	s0,sp,16
  return g(x);
}
  1a:	250d                	addiw	a0,a0,3
  1c:	60a2                	ld	ra,8(sp)
  1e:	6402                	ld	s0,0(sp)
  20:	0141                	addi	sp,sp,16
  22:	8082                	ret
```

所以在 `main` 中看不到其对 `g` 和 `f` 函数的调用，编译器在编译期就把真正要传入 `printf` 的值计算好放入 `a1` 中了。

### 函数 `printf` 位于什么地址？

搜索看到 `printf` 加载在 `0x0000000000000640` 。

```assembly
0000000000000640 <printf>:

void
printf(const char *fmt, ...)
```

### 在 `main` 中执行完跳转到 `printf` 的 `jalr` 指令之后，寄存器 `ra` 里的值是什么？

`ra` 寄存器用于保存返回地址，所以会指向 `jalr` 下一条指令的地址，也就是 0x40 。

```assembly
3c:	608080e7          	jalr	1544(ra) # 640 <printf>
exit(0);
40:	4501                li	a0,0
```

### 下面代码的输出是什么？如果 RISC-V 换成大端（big-endian），为了得到同样的输出，你应该把 i 设成什么值？需要把 57616 改成别的值吗？

```C
unsigned int i = 0x00646c72;
printf("H%x Wo%s", 57616, &i);
```

输出为 "HE110 World" 。大端序需要将 `i` 设置为 `0x726c6400` 。

57616 不需要修改，因为 `%x` 表示将 57616 使用十六进制输出，跟端序无关。

### 在下面的代码中，`y=` 后面会打印什么？（注意：答案不是一个具体的值。）为什么会这样？

```C
printf("x=%d y=%d", 3);
```

`y` 后面显然会输出一个随机整数。学过 pwn 的我自然知道这是一种格式化字符串漏洞。由于 `printf` 传入的字符串中期望两个可变参数，而源代码只传入了以一个。所以按照调用约定会将本应传入第二个参数的 `a2` 寄存器的值打印出来，这个值在调用时没有传入，是随机的。
